## Interface and visual identity — Beta 0 / 1.0.26300.308

- **pt-BR, es and en** selection in the startup menu and settings, covering menus,
  help, messages, dialogs and screens controlled by the app.
- Preference saved in `graphics.cfg` and loaded before initial dialogs;
  integration with the native file picker's language.
- Central catalog in [interface.json](xbox/locales/interface.json), generated
  headers and coverage/parity tests. This does not change game asset localization
  or game audio.
- **God of War III** display name in the manifest and interface. Internal identity
  `GodOfWar3Launcher`, publisher and technical `.appx` filename are retained for
  update compatibility; they are not the display title.
- Supplied splash logo and cover, with square/wide images, scale 100/200/400
  variants and MakePRI indexing in a single package. The high-resolution cover
  source is retained in the repository; tiles are generated by
  [generate_xbox_artwork.py](scripts/generate_xbox_artwork.py). Xbox shell image
  selection and caching require verification on an actual console.

## Advanced controls — since 1.0.26300.308

Menu integration, persistence, value validation and restart notices are work in
this fork. **The underlying graphics mechanisms already existed upstream.**

| Control | Purpose |
| --- | --- |
| Threaded command recording | Record commands on another thread. |
| Pipelined draw preparation | Overlap preparation and recording while preserving order. |
| Memory copy workers | Select zero, one or two copy workers. |
| Persistent pipeline cache | Reuse the cache between launches. |
| Driver pipeline binaries | Reuse binaries when supported by the driver. |
| Prepare graphics state in advance | Prepare Dozen state ahead of drawing. |
| Parallel shader cache loading | Warm up saved pipelines in parallel. |
| Upload buffer memory | Compare cached and uncached memory. |
| Log frame pacing and memory | Report presentation intervals, CPU and memory. |
| Log CPU frame stalls | Report compilation, recording and CPU waits. |
| Log resource loading | Report reads, copies and paging. |
| Log slow graphics commands | Report slow command recording on the CPU. |
| Log CPU/GPU synchronization | Report CPU submission and semaphore waits. |

Implementation: [spartanport_xbox_performance.h](gpu/shim/spartanport_xbox_performance.h).
Defaults and collection: [performance guide](xbox/PERFORMANCE.md)
([Brazilian Portuguese](xbox/PERFORMANCE.pt-BR.md)). Private overrides retain
precedence; diagnostics are disabled by default and add overhead when enabled.

## Profiling — since 1.0.26300.308

- Enable collection after reading settings and connect the collector to the
  presentation path.
- Histogram with no per-frame allocation, mean, maximum, p95/p99 estimates and
  counts of intervals above 50/100 ms, including long pauses.
- VMA heap counters replace scanning every allocation for the report.
- [Log analyzer](scripts/analyze_xbox_performance.py) aggregates FPS, waits and
  memory, with tests for settings, histograms and aggregation.

GPU memory is not GPU utilization or execution time. Wait diagnostics measure
the CPU side; we do not re-enable GPU timestamps or claim an FPS improvement.

## Withdrawn experiment: first-start preparation — 1.0.26300.436

This historical line **returns to .308** and reverts the rejected .343 changes.
Its release was deleted at the maintainer's request; the changes below **are not
included in Beta 0**.

- Check vertex/fragment shader indexes, compatible profiles and actual cache
  file sizes before treating the library as ready.
- Normal startup attempts to prepare a missing/incompatible library automatically.
- **Precompile shaders** prepares the library, warms up ten common texture upload
  converters (1D/2D, 8/16/32/64/128 bits) and previously recorded game pipelines.
- Warm converters at most once per app launch; normal startup waits for recorded
  pipeline warmup before starting the guest.
- On normal Xbox startup, a draw that depends on compilation waits for its shader
  or pipeline. This avoids dropping a draw that may write to a texture used later.
  Fast startup explicitly retains the earlier asynchronous behavior.
- Updated help in all three languages and native selftests for missing,
  incomplete, incompatible or truncated caches, alongside existing validation.

This prepares **converters and pipelines**, not textures/models the game has not
yet requested. Unknown states still require compilation on first use. There is
a tradeoff between complete drawing and pauses; the reported visual issue and
actual loading times still require testing on a console.

## Build and distribution

The expanded native shader selftest was added in the .436 line; Beta 0 retains
the tests and build configuration from its original commit.

- [Xbox workflow](.github/workflows/xbox.yml) builds Dozen on Windows/VS2022 and
  the app on Windows/VS2026, with pinned/cached dependencies and a DXC checksum.
- Translation/artwork tests, resource generation, shader selftest, native build,
  MakePRI, MakeAppx and test signing before making the package available.
- ZIP named **GOW3xbox<app version>.zip**, including `.appx` and VCLibs in `Dependencies`.
- Optional prerelease publication through manual dispatch, with provenance and
  installation documentation. [Policy and versions](RELEASES.md).

## Inherited features and unimplemented work

The loader/runtime, shadPS4 graphics translation, Dozen, paging, game patches,
audio/video, controller support and existing cache, readback and multithreading
paths come from earlier projects. Exposing a setting does not mean rewriting
those subsystems.

We did not implement new batching/instancing systems, GPU-driven rendering,
LOD/culling, progressive asset streaming, texture recompression, dynamic
resolution, working FSR on Xbox or new lighting/post-processing passes.
Infeasible proposals were left out at the maintainer's direction.

## Withdrawn changes

**1.0.26300.343** experimented with readback coherence, fair compilation
scheduling, smaller warmup batches and package name/metadata. After failure was
reported, these changes were **reverted**, preserving Git history. They are not
included in .436 and are not presented as maintained improvements.
